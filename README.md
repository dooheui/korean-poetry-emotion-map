## 1. 사용법

**① 시를 고르고 → ② 감정 이름을 누르고 → ③ 계산과 해석을 비교해 보세요.**

**첫 화면 구성(2026-11-22 정리):** PC는 왼쪽 작품 목록(F-01), 가운데 원문·감지 시어·행별 감정(F-02·F-04), 오른쪽 지배 정서·전체 감정 비율·주제·3문장 이상 해석(F-03·F-05)을 함께 배치했습니다. 1180px 이상·높이 650px 이상에서는 첫 분석 영역을 `100svh − 156px` 높이로 설계하고, 긴 원문은 안에서 스크롤합니다. 감정 10개는 5행으로 나눕니다. 작은 화면에서는 자동으로 높이를 풀고, 768px 이하에서는 한 열로 쌓습니다. 기술명세서 6장의 ‘스크롤 없이 또는 한 번의 스크롤’ 기준에 맞춰 부가 설명을 아래로 이동했습니다. 실제 브라우저의 글꼴·확대율에 따른 배치는 배포 후 재확인이 필요합니다.

**글꼴:** 시 본문·작품 제목·해석은 Google Fonts의 **고운바탕(Gowun Batang)**, 조작부와 수치는 **고운돋움(Gowun Dodum)**을 사용합니다. PC 본문 17px, 해석 15px, 제목 27px를 기준으로 하고, 넓게 읽기는 20px 이상입니다. 외부 글꼴 실패 시 시스템 글꼴로 대체합니다. 옛한글은 CJK 명조 계열 대체 글꼴을 함께 지정했습니다.

1. 왼쪽 목록에서 작품을 고릅니다. 제목·시인으로 검색할 수 있습니다. 모바일에서는 작품 목록을 가로로 넘깁니다.
2. 본문은 연·행 구분을 보존합니다. ‘감지 표시’로 밑줄을 켜고 끄고, 행을 누르면 감지 시어와 범주별 횟수를 봅니다. ‘넓게 읽기’로 전체 시를 큰 글씨로 읽고 닫기 또는 Esc로 돌아옵니다.
3. 첫 결과 상단에는 현재 결합 결과의 **지배 정서 이름·비율·계산 기준**을 표시합니다. 감정 이름을 누르면 근거를 확인할 수 있습니다. **사전 분석 / 해석 프로필 / 결합 결과**의 세 값과 차이의 이유는 바로 다음 ‘계산과 해석 사이’에서 확인합니다.
4. 감정 비율 목록의 이름을 누르면 ✓ 표시와 함께 해당 시어·행이 강조됩니다. 다시 누르거나 ‘강조 해제’로 해제합니다. 근거 시어가 없고 프로필에서만 온 값은 별도로 안내하며 원문 근거를 만들어 내지 않습니다. 모바일에서는 ‘본문에서 보기’를 이용할 수 있습니다.
5. ‘계산과 해석 사이’의 **사전 분석 근거**에서 전체 감지 횟수와 감지 행 수를 확인합니다. 예: ‘시어 8회 감지 · 전체 16행 중 6행에서 감지’. 반복은 나온 만큼 세며, 펼침 설명에는 서로 다른 사전 시어의 종류 수도 표시합니다. 이 수치는 정확도·신뢰도·감정 강도가 아닙니다. 가중치를 바꿔도 사전 근거의 양은 같습니다.
6. 사전 반영 비율은 **0~100%, 10% 단위**입니다. 0%는 해석 프로필, 100%는 사전만 적용합니다. 최종 벡터에 의존하는 차트·추천·히트맵·지도·이미지는 함께 바뀌고 행별 감지 횟수는 바뀌지 않습니다. 감지 0회에서 사전 100%면 비율과 지배 정서를 만들지 않습니다.
7. 제목 아래 ‘원문 출처 ↗’로 본문 출처를 새 창에서 엽니다. ‘본문 출처와 판본’에는 옮긴 방법, 수정 이력과 연도 근거가 있습니다. **발표·시집 수록·창작 연도**를 구분하며, 시집 수록 연도만 확인된 경우 이를 최초 발표라고 표시하지 않습니다.
8. **‘이 시 공유하기’**는 작품과 가중치를 담은 링크를 복사합니다. 자동 복사가 거절되면 선택 가능한 링크가 나타납니다. 작품이나 가중치를 바꾼 뒤에는 다시 복사합니다. 공유되는 것은 작품 ID와 가중치뿐이며 독자 메모·직접 입력문은 포함되지 않습니다.

### 공유 주소 규칙

예: https://dooheui.github.io/korean-poetry-emotion-map/?p=geunal&w=100

| 파라미터 | 의미 | 처리 |
|---|---|---|
| `p` | 수록 작품의 ID | 없거나 잘못되면 첫 작품 |
| `w` | 사전 반영 비율(%) | `0,10,20,…,100` 허용. 없거나 범위·형식·단위가 잘못되면 50% |
| `check=1` | 엔진·데이터 자체 점검 | 점검 영역을 표시. 공유 링크에는 포함하지 않음 |

웹에서는 현재 도메인과 하위 경로로 공유합니다. 내려받은 파일을 `file://`로 열었다면 다른 사람이 접근할 수 없는 로컬 경로 대신 위 GitHub Pages 주소를 사용합니다. 이 경우 공유 상대에게 보이는 버전은 실제 배포된 버전입니다.

입력문은 텍스트로 처리하며 외부로 전송하거나 저장하지 않습니다. 감정어를 못 찾으면 감정이 없다고 단정하지 않고 안내합니다. 글꼴은 외부 Google Fonts에서 불러오되 실패하면 시스템 글꼴을 사용합니다. 페이지의 표·차트는 필요한 경우 자기 영역 안에서 가로 스크롤합니다.

## 2. 수록 시인과 작품

20편을 수록했습니다. 신규 작품 표시는 과제지시서에 나열된 예시 시인(김소월·윤동주·한용운·이육사·정지용·김영랑) 이외의 시인 작품에 보수적으로 붙였습니다. 이 기준으로도 새 작품이 5편 이상입니다. 같은 시인의 다른 작품은 이번 수정에서 예시와의 중복을 다시 대조하지 않아 신규 표시에서 제외했습니다. 사망 연도는 데이터에 기록된 값으로 모두 과제의 1962년 이하 기준을 충족합니다. 시 본문 전체와 상세 판본 정보는 웹앱에서 확인합니다.

연도는 첨부본에 있는 서지 정보를 유지하되 표시 기준을 구분했습니다. 최초 발표가 미확인인 작품은 확인된 시집 수록 연도를 표시합니다. 이번 수정에서는 외부 서지 자료와 원전 스캔을 독립적으로 재대조하지 않았습니다. 신규 표시가 있는 작품은 12편입니다.

## 3. 감정 범주 정의와 분석 방법

과제지시서 필수 2(감정 분석)의 요구에 맞춰 범주·비율·행 단위 감정·지배 정서·주제·해석을 모두 계산하거나 작성했습니다. 정량 방법은 **방법 A 감정 사전**입니다.

| 과제지시서 필수 2 요구 | 이 웹앱 |
|---|---|
| 감정 범주 6~10개, 범주마다 한 문장 정의 | 10개, 아래 3.1 |
| 시마다 감정 비율(합 100%) | 사전 비율과 해석 프로필을 결합해 계산, 화면 합계 정확히 100.0%(3.3) |

**가까운 범주를 가르는 기준**

- 슬픔 ↔ 그리움: 아픔 자체가 중심이면 슬픔, 떨어진 대상을 향해 다가가려는 마음이 중심이면 그리움.
- 슬픔 ↔ 허무: 무엇을 잃어 아픈 것이면 슬픔, 의미 자체가 사라졌다고 느끼면 허무.
- 기쁨 ↔ 평온: 들뜨고 솟구치면 기쁨, 가라앉아 고요하면 평온.
- 기쁨 ↔ 희망·의지: 이미 이루어진 좋은 일이면 기쁨, 아직 오지 않은 것을 기다리거나 버티는 마음이면 희망·의지.
- 사랑 ↔ 그리움: 대상에게 지금 다가가는 마음이면 사랑, 대상이 없거나 멀어서 생기는 마음이면 그리움.
- 부끄러움·성찰 ↔ 불안·공포: 자기 잘못을 돌아보면 부끄러움·성찰, 바깥의 위협이나 정체 모를 것을 두려워하면 불안·공포.
- 분노 ↔ 슬픔: 해친 대상을 향해 맞서는 힘이 있으면 분노, 당한 일을 아파하는 데 머물면 슬픔.

**여러 범주에 걸치는 낱말의 규칙.** 한 시어는 한 범주에만 넣습니다(`buildMatcher`가 중복 등록을 오류로 막음). 둘 이상에 걸치는 낱말은 위 기준으로 가장 직접 가리키는 범주 하나를 골랐습니다. 예: ‘이별’은 지금의 아픔이라 슬픔, ‘옛날’은 지나간 때를 향하는 말이라 그리움, ‘시들’은 사라짐이라 허무. 정하기 어려운 낱말(‘꿈’, ‘님’, ‘홀로’ 등)은 넣지 않았습니다.

### 3.2 감정 사전(방법 A)

위치: `index.html` 안의 `LEXICON` 부분(현재 v3, 시어 205개 + 차단어 2개). 웹앱 맨 아래 ‘범주와 사전’에서도 전체 목록을 볼 수 있습니다.

#### 만든 방법

1. 예시 앱 사전(8범주 133개)을 출발점으로 범주마다 낱말을 하나씩 검토했습니다.
2. 10범주 정의에 맞춰 직접 감정을 가리키는 말(감정 형용사·동사의 어간과 활용형, 감정 명사)만 남기고, 수록 20편 본문을 읽으며 실제 표기(옛 표기·한자어)를 더했습니다.
3. 사전으로 20편을 돌려 보고 나온 오탐을 검증 사례로 기록한 뒤 필요한 만큼만 고쳤습니다. 감정 결과를 해석에 맞추려고 낱말을 더하지는 않았습니다.

외부 감정 사전이나 논문의 목록을 옮기지 않았습니다.

### 3.3 계산 방법

방식 1(브라우저가 사전으로 계산)입니다. 엔진은 `index.html` 안의 `PoemEngine` 부분입니다.

**전처리**

- 줄바꿈으로 나누고 앞뒤 공백을 지웁니다. 빈 줄은 연 구분에만 쓰고 분석 행에서 뺍니다(행 번호는 빈 줄을 빼고 1부터).
- 옛한글 합용병서(ᄭ ᄯ ᄲ ᄶ)는 **분석용 사본에서만** 된소리(ㄲ ㄸ ㅃ ㅉ)로 바꾸고 한 글자로 합칩니다. 반복 부호 々는 앞 글자로 폅니다. 일치 위치는 원래 본문 위치로 되돌리므로 화면 본문은 판본 그대로입니다. 예: 「나의 침실로」의 ‘ᄯᅥᆯ며’는 ‘떨며’(불안·공포)로 셉니다.

**매칭 규칙**

- 모든 시어와 차단어를 **길이가 긴 것부터** 정렬해 특수문자를 이스케이프한 뒤 **하나의 정규식**으로 만듭니다(`'gu'` 플래그).
- 정규식은 왼쪽부터 겹치지 않게 일치하므로 같은 자리를 두 번 세지 않습니다(예: ‘구슬픈’은 ‘슬픈’으로 또 세지 않음).
- 같은 시어가 다른 자리에 또 나오면 나온 만큼 셉니다(예: 「오감도」 ‘무섭’ 13회).
- 행마다 범주별 개수 `counts`와 일치 목록 `hits`(시어, 범주, 시작·끝 위치, 화면 표기)를 저장합니다.

**계산식**

- 사전 벡터: `v_lex(e) = Σ_l c(l, e) / Σ_l Σ_e c(l, e)`. 감지가 하나라도 있으면 합이 1입니다.
- 감지가 0이면 `v_lex`는 영벡터이고 지배 정서는 `null`입니다. **균등 비율이나 지배 정서를 지어내지 않습니다.**
- 해석 프로필 결합: `p̂ = profile / Σ profile`, `v = normalize((1 − w)·p̂ + w·v_lex)`. 프로필이 없거나 `w = 1`(사전 100%)이면 `v = v_lex`입니다. 사전 100%에서는 프로필이 결과를 덮어쓰지 않습니다.
- 지배 정서: `v`의 최댓값 범주입니다. 동률이면 범주 순서상 앞의 것을 표시하고, 동률인 범주를 화면에 함께 알립니다.
- 결과 객체(방식 1의 내부 구조): `{ id, vec, dominant, lines:[{no, stanza, text, counts, hits}], method: 'lexicon' | 'hybrid' }`.
- 화면 백분율은 최대 나머지 방식으로 반올림해 합계가 정확히 100.0%입니다(히트맵 칸의 정수 표시는 99~101 가능, 화면에 안내).
- 근거 경고: 사전 감지가 1~2개면 ‘한두 낱말에 좌우된다’는 주의를 띄웁니다(검증 사례 2에서 추가).

**유사도·추천**

- 수록작끼리는 **같은 기준**인 현재 가중치의 결합 벡터 `v`끼리 코사인 유사도를 계산해, 자기 자신을 빼고 상위 3편을 보입니다. 카드의 지배 정서와 설명도 같은 벡터에서 계산합니다.
- ‘내 시 분석’은 해석 프로필이 없으므로 **입력 시의 사전 벡터와 수록작의 사전 벡터끼리** 비교합니다. 그래서 가중치를 바꿔도 내 시 추천은 그대로입니다.
- 추천 이유: 양쪽 모두 10% 이상인 감정만 ‘함께 큰 감정’이라 부르고, 10%p 이상 차이 나는 감정 가운데 가장 큰 것을 ‘가장 큰 차이’로 보입니다. 기준을 넘는 감정이 없으면 없다고 씁니다.
- 영벡터는 유사도를 정의하지 않습니다. 기준이 영벡터면 추천하지 않고, 상대가 영벡터면 후보에서 뺍니다.
- 동률이면 수록 순서가 앞선 작품을 먼저 두고, 3위 경계에 동률이 있으면 알립니다.
- 유사도는 **감정 비율이 닮았다**는 뜻일 뿐, 주제나 문학적 의미가 비슷하다는 뜻이 아닙니다.

**감성 지도(PCA)**

- 최종 벡터에서 평균을 빼고 공분산 행렬의 상위 고유벡터 2개를 거듭제곱법으로 구해 사영합니다.
- 축 이름은 적재값이 큰 감정(양·음 방향 각각 상위 2개)입니다. 영벡터 작품은 지도에서 빼고 그 사실을 표시합니다.
- 두 축의 설명력을 더한 누적 설명력을 계산해 “두 축은 전체 감정 벡터 분산의 약 ○○%를 보여 줍니다”로 보이고, 나머지 분산은 지도에 나타나지 않으므로 가까운 점도 원래 감정 구성이 모두 같지는 않다고 안내합니다. 가중치를 바꾸면 다시 계산합니다.

### 3.4 지배 정서·주제·해석

- **세 가지 결과**: ‘계산과 해석 사이’는 사전 분석(`v_lex`), 해석 프로필(`p̂`), 결합 결과(`v`)에서 각각 가장 높은 감정과 비율을 따로 보입니다. 첫 화면에는 결합 지배 정서·비율과 주제·해석을 우선 표시합니다. 숫자는 모두 엔진이 그때그때 계산하며 고정값이 아닙니다. 두 결과가 다를 때 이를 오류로 숨기거나 가중치로 없애지 않고, 차이의 이유를 문장으로 보입니다.
  - 문장 앞부분은 계산에서 만듭니다: 사전이 실제로 센 시어 이름, 두 결과가 같은지, 동률인지, 감지 0건인지.
  - 뒷부분은 작품마다 따로 쓴 해석 근거(`contrast`)입니다. 일괄 복사한 문장이 아닙니다.
- **지배 정서**는 결합 벡터에서 가장 큰 범주이고, 동률이면 범주 순서상 앞의 것을 표시하면서 동률 사실을 함께 알립니다. 사전 감지가 0건이고 사전 100%면 지배 정서를 정하지 않습니다.
- **주제·화자·표현 기법·핵심 구절·해석**은 작품마다 `index.html` 안의 작품 데이터(`window.POEM_DATA`)에 들어 있습니다. 해석은 3문장 이상이고, 핵심 구절은 본문의 한 행과 글자 그대로 같습니다(자체 점검으로 확인).
- **해석 프로필**(범주별 0~1 강도)은 사람이 검토해 정하는 해석 값이며 모델 예측이나 정답이 아닙니다. 감정 비율도 시가 그 감정일 확률이나 정확도가 아니라 감정 구성입니다. 프로필은 사전이 읽지 못하는 반어·문맥을 반영하려고 씁니다. 자세한 근거와 한계는 [9장](#section-9)에 있습니다.

## 4. 검증 사례

아래 수치는 사전 v3과 현재 작품 데이터로 엔진을 실행해 얻은 값입니다(제작 환경에서 계산, 2026-11-21~22). 이번 화면 개선에서 사전·본문·해석 프로필은 바꾸지 않았으므로 수치도 같습니다. 웹앱에서 같은 작품을 열고 가중치를 맞추면 같은 값을 확인할 수 있고, 각 작품의 **분석이 놓친 부분** 카드는 현재 계산 결과와 연결되어 있습니다. 개선 가운데 실제로 구현한 것은 사례 2(근거 경고)와 사례 5(차단어)이고, 나머지는 제안입니다.

### 사례 1. 「절정」 — 감지 0건

- **해당 행**: 전 8행. 예: ‘서릿발 칼날진 그 위에 서다’, ‘겨울은 강철로 된 무지갠가보다.’
- **계산**: 감지 시어 0개(감지 행 0/8). 사전 100%에서는 영벡터라 비율·지배 정서를 만들지 않고 추천도 하지 않습니다. 가중치 50%에서는 사전 쪽이 0이라 프로필만 남아 희망·의지 53.3%, 불안·공포 26.7%, 슬픔 20.0%가 되고 추천은 청포도 82.2%, 쉽게 씌어진 시 62.6%, 그날이 오면 51.0%입니다.
- **문학적 해석**: 극한으로 몰린 상황(채찍, 고원, 칼날)과 그것을 넘어서는 역설(강철 무지개)로 비장한 의지를 전하는, 감정의 밀도가 아주 높은 시입니다.
- **어긋남**: 정서가 강한 시인데 사전은 아무것도 읽지 못합니다.
- **원인**: 사전은 감정을 직접 가리키는 말만 셉니다. 이 시는 감정어 없이 이미지와 상황으로만 정서를 만듭니다.
- **개선 방향(제안)**: 이미지어(채찍·칼날 등)를 감정에 고정하면 다른 시에서 오탐이 늘어나므로 넣지 않았습니다. 문장 단위 모델(예: 한국어 BERT 감정 분류)을 쓰면 이미지 문장도 점수를 받을 수 있지만, 근대 표기와 비유에서 잘 맞는지는 따로 검증해야 합니다.
- **남은 한계**: 감지 0건을 숨기지 않고 ‘계산하지 않음’으로 보이게 했습니다. 가중치 50%에서 보이는 값은 전부 사람이 정한 프로필에서 나온 값이라는 점을 화면에 적어 둡니다.

### 사례 2. 「남으로 창을 내겠소」 — 한 낱말이 결과를 정함 (개선 일부 구현)

- **해당 행**: 12행 ‘웃지요.’ 하나만 감지(감지 행 1/12).
- **계산**:

  | | 결과 | 지배 정서 |
  |---|---|---|
  | 사전만 | 기쁨 100% | 기쁨 |
  | 가중치 50% | 기쁨 60.7%, 평온 32.2%, 사랑 7.1% | 기쁨 |
  | 프로필만 | 평온 64.3%, 기쁨 21.4%, 사랑 14.3% | 평온 |

  사전만으로 추천하면 빼앗긴 들에도 봄은 오는가 96.2%, 그날이 오면 91.3%처럼 기쁨이 높은 시가 나옵니다.
- **문학적 해석**: ‘왜 사냐건 / 웃지요.’는 즐거운 웃음보다 삶의 이유를 따지지 않는 달관의 웃음입니다.
- **어긋남**: 평온·달관의 시가 기쁨 100%가 됩니다.
- **원인**: 근거가 낱말 하나뿐인데 비율로 바꾸면 100%가 됩니다. 또 웃음이 무엇을 뜻하는지는 문맥(앞의 ‘왜 사냐건’, 시 전체의 담담한 어조)이 정합니다.
- **개선(구현)**: 사전 감지가 1~2개면 ‘한두 낱말에 크게 좌우된다’는 경고를 띄웁니다(이 작품 1개, 「청포도」 2개). 숫자는 바꾸지 않고 감지 근거가 적다는 한계만 알립니다. 구현 전에는 같은 화면에 경고가 없었고, 후에는 지배 정서 아래 경고가 나옵니다.
- **남은 한계**: 경고는 해석을 고쳐 주지 않습니다. 가중치 50%에서도 기쁨이 지배 정서로 남습니다.

### 사례 3. 「빼앗긴 들에도 봄은 오는가」 — 밝은 정경과 상실

- **해당 행**: 10행 ‘…반갑다웃네’, 11행 ‘고맙게 잘자란 보리밧아’, 16행 ‘…엇게춤만 추고가네’, 27행 ‘푸른웃슴 푸른설음이 어우러진사이로’. 마지막 행 ‘그러나 지금은―들을 ᄲᅢ앗겨 봄조차 ᄲᅢ앗기것네’는 감지 없음.
- **계산**: 감지 7개(감지 행 5/29).

  | | 결과 | 지배 정서 |
  |---|---|---|
  | 사전만 | 기쁨 71.4%, 슬픔 14.3%, 평온 14.3% | 기쁨 |
  | 가중치 50% | 기쁨 45.0%, 슬픔 22.0%, 사랑 13.0% | 기쁨 |
  | 프로필만 | 슬픔 29.7%, 사랑 25.9%, 기쁨 18.5% | 슬픔 |

  분노는 사전에서 0입니다.
- **문학적 해석**: 봄 들판과 하나 되는 기쁨이 길게 이어지지만, 첫 행의 물음과 마지막 행의 깨달음이 그 기쁨 전체를 빼앗긴 땅의 비애로 바꿉니다.
- **어긋남**: 사전은 정경의 밝은 낱말을 세어 기쁨을 지배 정서로 냅니다.
- **원인**: 사전은 모든 행을 같은 무게로 셉니다. 시의 구조(마지막 행의 반전)를 모르고, 핵심어 ‘빼앗기다’는 사전에 없습니다.
- **실험(채택하지 않음)**: ‘빼앗’을 사전에 넣어 보았습니다. 슬픔에 넣으면 기쁨 50%, 슬픔 40%이고, 분노나 허무에 넣으면 기쁨 50%, 분노(허무) 30%입니다. 세 경우 모두 지배 정서는 여전히 기쁨입니다. 다른 19편에는 영향이 없었습니다. ‘빼앗김’이 슬픔·분노·허무 가운데 어디인지 정하기 어렵고, 낱말 하나로는 구조 문제가 풀리지 않아 넣지 않았습니다.
- **개선 방향(제안)**: 마지막 연·행에 가중치를 주거나 ‘그러나’ 뒤 문장을 따로 보는 규칙은 다른 시에서 맞는지 확인해야 하므로 제안으로만 둡니다.

### 사례 4. 「오감도 시제1호」 — 반복

- **해당 행**: 3~15행 ‘第一의兒孩가무섭다고그리오。’ … ‘第十三의兒孩도무섭다고그리오。’(13행이 번호만 다름), 16~20행 ‘무서운兒孩’, ‘무서워하는兒孩’.
- **계산**: 감지 19개(감지 행 18/22), 사전만 불안·공포 100%. 가중치 50%에서는 불안·공포 82.1%, 허무 17.9%입니다.
- **실험(채택하지 않음)**: 번호만 다른 행을 한 번만 세면 감지는 8개로 줄지만 비율은 불안·공포 100% 그대로입니다. 비율은 정규화되므로, 반복은 한 범주만 있는 시에서는 비율을 바꾸지 않습니다. 여러 범주가 섞인 시에서는 반복된 쪽으로 기웁니다(예: 「나는 왕이로소이다」 눈물·울음 31개로 슬픔 83.8%).
- **문학적 해석**: 공포의 주체(무서운 아이)와 대상(무서워하는 아이)이 뒤섞이고, 마지막에 상황 자체가 부정되면서 이유도 출구도 없는 불안과 부조리가 남습니다.
- **어긋남**: 방향(불안)은 맞지만 ‘무서운’과 ‘무서워하는’의 차이, 마지막 연의 부조리(허무)는 읽지 못합니다. 100%라는 숫자가 시의 복잡함을 지나치게 단순하게 보이게 합니다.
- **원인**: 사전은 누가 누구를 두려워하는지(주체/대상)와 진술의 부정을 구별하지 못합니다.
- **개선 방향(제안)**: 반복 행 할인(같은 행 문자열은 1회로 계산) 옵션을 두고 원래 값과 함께 보여 주는 방법이 있습니다. 반복 자체가 시의 의미인 경우도 있어 기본값으로는 넣지 않았습니다.

### 사례 5. 부분 문자열 오탐 — ‘바라보고’·‘바라다보아야’ (개선 구현)

- **해당 행**: 「돌담에 속삭이는 햇발」 8행 ‘실비단 하날을 바라보고십다’, 「목마와 숙녀」 16행 ‘늙은 여류작가의 눈을 바라다보아야 한다’.
- **문제**: 희망 시어 ‘바라’(바라다, 바라는)가 ‘바라보다’ 속에서 일치해 희망으로 세어졌습니다.
- **원인**: 어간 부분 문자열 일치. ‘바라’를 빼면 「청포도」 ‘내가 바라는 손님’, 「참회록」 ‘무슨 기쁨을 바라’, 「쉽게 씌어진 시」 ‘나는 무얼 바라’ 같은 바른 감지를 잃습니다.
- **개선(구현, 사전 v2)**: 차단어 ‘바라보’, ‘바라다보’를 같은 정규식에 넣었습니다. 긴 것이 먼저 일치하므로 그 자리에서는 ‘바라’가 세어지지 않습니다.
- **전후 결과**(가중치와 무관한 사전 결과):

  | 작품 | v1(차단어 없음) | v2(차단어 있음) |

### 사례 6. 「별 헤는 밤」 — 부정 표현

- **해당 행**: 3행 ‘나는 아무 걱정도 없이’.
- **계산**: ‘걱정’이 불안·공포로 세어져 사전만 결과에 불안·공포 10.0%가 생깁니다(전체 감지 10개: 그리움 40, 슬픔 30, 사랑·부끄러움·불안 각 10). 가중치 50%에서는 불안·공포 5.0%입니다.
- **문학적 해석**: 걱정이 ‘없이’ 별을 헤는 평온한 도입입니다. 불안은 없습니다.
- **어긋남**: 부정된 감정이 그 감정으로 세어집니다.
- **원인**: 사전은 시어 뒤의 ‘없이’, ‘않’, ‘말아라’ 같은 부정을 보지 않습니다.
- **조사**: 시어 뒤 8글자 안에 부정 표현(없·않·못·말·아니)이 오는 경우를 20편에서 모두 찾았더니 5곳이었습니다.

  | 작품 | 구절 | 정말 부정인가 |
  |---|---|---|
  | 별 헤는 밤 | 걱정도 없이 | 부정 |
  | 나는 왕이로소이다 | 울지 말아라 | 부정(금지) |
  | 나는 왕이로소이다 | 시름없이 울었소이다 | 아님(‘시름없이’는 멍하니라는 뜻) |
  | 접동새 | 죽어서도 못잊어 | 아님 |
  | 접동새 | 못잊어 차마 못잊어 | 아님(부정이 아니라 강조) |

- **개선 방향(제안)**: 이 조사대로라면 ‘뒤에 부정어가 오면 빼기’ 같은 규칙 하나는 5곳 중 3곳을 틀리게 처리합니다(특히 「접동새」의 핵심 그리움을 지움). 부정 처리는 단순 규칙으로 해결되지 않아 구현하지 않았고, ‘걱정도 없이’처럼 확인된 구절만 차단어로 넣는 방법도 특정 작품에 맞추는 것이라 보류했습니다.

### 사례 7. 「세월이 가면」 — 낱말의 존재와 감정 상태

- **해당 행**: 8행 ‘사랑은 가고’, 16행 ‘우리들 사랑이 사라진다 해도’, 7행 ‘가로등 그늘의 밤을 잊지 못하지’.
- **계산**: 감지 4개(감지 행 3/20).

  | | 결과 | 지배 정서 |
  |---|---|---|
  | 사전만 | 사랑 50.0%, 그리움 25.0%, 허무 25.0% | 사랑 |
  | 가중치 50% | 사랑 34.1%, 그리움 32.9%, 허무 21.6%, 슬픔 11.4% | 사랑 |
  | 프로필만 | 그리움 40.9%, 슬픔 22.7%, 사랑 18.2%, 허무 18.2% | 그리움 |

  사전만으로 추천하면 논개 77.0%, 나의 침실로 69.3%처럼 ‘사랑’이 높은 시가 나옵니다. 가중치 50%에서는 별 헤는 밤 71.7%, 나의 침실로 70.3%, 사슴 64.9%입니다.
- **문학적 해석**: 사랑은 이미 떠났고, 이름도 잊었지만 눈동자와 입술은 가슴에 남아 있다는 그리움의 시입니다.
- **어긋남**: ‘사랑’이라는 말이 나오면 사랑으로 세지만, 이 시에서 사랑은 지금의 감정이 아니라 지나간 대상입니다. 「논개」의 ‘사랑보다도 강하다’도 비교의 기준으로 쓰인 사랑입니다.
- **원인**: 사전은 낱말이 가리키는 것이 화자의 현재 감정인지, 이야기의 대상(주제어)인지 구별하지 못합니다.
- **개선 방향(제안)**: ‘사랑’, ‘이별’ 같은 말은 주제어로 따로 표시하고 감정 계산에서는 가중치를 낮추는 방법이 있습니다. 어떤 말을 주제어로 볼지 기준을 정하고 다른 시에 미치는 영향을 확인해야 해서 이번에는 구현하지 않았습니다.

> 각 사례의 ‘문학적 해석’ 문장은 Claude가 쓴 초안을 바탕으로 합니다(6장). 수치·행·원인은 엔진 실행 결과와 맞춰 두었습니다.

## 5. 한계와 개선 방향

**사전 방식의 한계**

- 반어·부정·가정·비교·주체와 대상을 읽지 못합니다(사례 3·4·6·7). 「그날이 오면」의 ‘기뻐서 죽사오매’, ‘울며 뛰며’도 슬픔으로 세어집니다.
- 감정어가 없는 시는 0건이 됩니다(사례 1). 감지가 적으면 비율이 한두 낱말에 좌우됩니다(사례 2).
- 어간 일치 오탐은 알려진 것만 차단어로 막을 수 있습니다(사례 5).
- 행마다 무게가 같아 시의 구조(마지막 행의 반전 등)를 반영하지 못합니다.

**데이터의 한계**

- 20편 가운데 14편은 원전 지면과 대조하지 못했습니다([12장](#section-12)).
- 일부 발표 연도는 최초 지면을 확인하지 못해 시집 수록 연도를 썼습니다.

**해석 프로필의 한계**

- 한 사람(초안은 AI)의 읽기이고, 정답 데이터가 없어 정확도를 계산하지 않았습니다.
- 여러 독자의 프로필을 모아 평균과 편차를 보이면 해석의 폭을 보여 줄 수 있습니다. 독자 메모는 그 출발점이지만 지금은 개인 기기에만 저장됩니다.

**개선 방향**

- 반복 행 할인, 주제어 표시, 마지막 연 가중 같은 옵션을 켜고 끌 수 있게 해 전후 결과를 나란히 보여 주기.
- 문장 단위 모델 결과를 미리 계산해 `results.json`으로 함께 비교하기(방식 2).

## 9. 해석 프로필

- 작품마다 `profile`(범주별 0~1 강도)을 **사람이 정한 해석 값**으로 넣었습니다. 모델 출력이 아닙니다.
- 근거는 작품마다 `profileNote`에 한두 문장으로 적었고, 화면 ‘계산과 해석 사이’에 보입니다. 예: 「남으로 창을 내겠소」는 ‘웃지요’를 달관의 웃음으로 읽어 평온을 가장 높게 두었습니다.
- 작품을 고를 때 붙인 편집용 라벨 `group`(어떤 정서를 대표하도록 골랐는지)은 프로필이나 결과를 만드는 데 쓰지 않았습니다. 실제로 6편은 프로필의 가장 높은 범주가 `group`과 다릅니다(그날이 오면 joy→hope, 돌담 joy→calm, 알 수 없어요 love→long, 논개 anger→love, 빼앗긴 들 anger→sad, 세월이 가면 void→long).
- **한계**: 프로필은 한 사람의 읽기입니다. 결합 결과가 사전만 결과와 많이 다르거나 적게 다르다고 해서 어느 쪽이 더 정확하다고 말할 수 없습니다. 정답 데이터가 없어서 정확도를 계산하지 않았습니다.
- 주제·해석·프로필과 차이 설명 문장은 Claude가 작성한 초안을 바탕으로 합니다(6장). 외부 해설서나 논문을 옮기지 않았으므로 해석 참고문헌(`interpRefs`)은 비어 있습니다.

## 12. 본문 대조 요약

아래는 첨부된 기존 README와 작품 데이터에 기록된 대조 이력입니다. 이번 UI 수정에서는 원전 스캔 대조를 새로 수행하지 않았습니다. 따라서 아래의 ‘대조’는 이전 제작 기록을 뜻합니다.

**기존 제작 기록의 원칙**

- 본문은 기억으로 쓰거나 다듬지 않았습니다. 위키문헌 문서를 MediaWiki API로 내려받아 그대로 저장하고, 스크립트로 본문을 뽑았습니다(원본 파일과 스크립트는 제작 환경에 있고 저장소에는 넣지 않았습니다).
- 한 작품에는 한 판본만 쓰고 판본을 섞지 않았습니다. 옛 표기·한자·이상의 붙여쓰기·문장부호는 판본 그대로 둡니다.
- ‘대조했다’는 말은 스캔 이미지를 실제로 열어 한 줄씩 본 6편에만 씁니다. 나머지 14편은 위키문헌 본문을 글자 그대로 옮겼지만 원전 지면과는 대조하지 못했습니다.
- 이번 수정에서도 시 본문과 저장된 연도 값은 바꾸지 않았습니다. 발표·시집 수록·창작이라는 화면 표시만 데이터의 기준에 맞췄습니다.

**스캔 대조 방법**

- 「참회록」: 초판 끝의 창작 날짜 ‘(1924)’는 1942의 오식으로 보고 날짜 줄을 본문에서 뺐습니다.

## 14. 파일 구조와 배포

```text
korean-poetry-emotion-map/
├── index.html   화면·스타일·시 데이터·사전·엔진·동작을 포함한 단일 파일
└── README.md    과제 설명·검증 사례·사용법
```

**로컬 실행:** `index.html`을 내려받아 브라우저에서 엽니다. 별도 빌드·서버 설치가 필요하지 않습니다. 외부 글꼴이 로드되지 않으면 시스템 글꼴로 표시합니다. 공유 기능은 로컬 경로 대신 배포 주소를 복사합니다.

**배포:** 공개 저장소의 최상위에 정확히 `index.html`, `README.md`라는 이름으로 올려 기존 파일을 교체합니다. 설정의 Pages에서 `main` 브랜치 `/ (root)` 배포를 사용합니다. 완료 여부는 GitHub의 Actions/Pages에서 확인하고 웹앱을 새로 고침합니다. 이 파일을 받는 것만으로 GitHub의 기존 페이지가 바뀌지는 않습니다.

수정할 때는 `index.html` 안의 `<style>`, `window.POEM_DATA`, `LEXICON`, `PoemEngine`, 마지막 화면 로직 스크립트를 구분해 편집합니다. 사전·본문·프로필을 바꿨다면 분석과 검증 사례 수치를 다시 확인해야 합니다.
